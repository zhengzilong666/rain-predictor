# MLflow 实验追踪总结

## 1. 实验对比
本项目使用 MLflow 追踪了两个实验：
1. **Baseline_Model**：使用 v1 原始数据，未进行特征优化，参数为 `n_estimators=10`, `max_depth=3`。
2. **Improved_Model**：使用 v2 清洗后的数据，并且剔除了冗余特征（仅保留湿度和降雨量），参数为 `n_estimators=50`, `max_depth=10`。

## 2. 生产模型选择
我认为 **Improved_Model** 值得上线到生产环境。
**原因如下**：
- 经过 DVC 的数据清洗和特征选择，模型过滤了大量噪声（如无关联的温度、风向等），能够更纯粹地学习到高湿度、高降雨量与降雨的因果逻辑。
- 相比基线模型，Improved 模型在 F1-Score 和 Accuracy 上均有显著提升，泛化能力更强。

## 3. 核心优化指标
本项目重点优化的指标是 **F1-Score**。
**原因**：在气象预测这种场景下，虽然 `Accuracy` 很重要，但由于“下雨”通常属于少数类，如果单纯追求准确率，模型容易陷入“永远预测不下雨”的懒惰状态。**F1-Score 是精确率和召回率的调和平均**，能够真实反映出模型对“降雨”这类关键事件的捕捉能力。对于用户而言，漏报一场大雨的代价远大于误报，因此 F1 更能反映模型的业务价值。

## 4. 代码与数据版本绑定
在 `train.py` 中，我通过代码自动获取了当前的 `Git Commit SHA` 和 `DVC 数据集哈希`，并将其作为 Tag 记录在 MLflow 中，完全实现了“准确追踪哪个数据集版本和代码版本产出了该模型”。
